# 个人推荐后端与数据库交接

## 当前架构

选课咨询前端 → /api/students → personal.py 对话与学习服务 → solver.py → 推荐结果。

前端不再执行对话解析或偏好学习。localStorage 仅保存 coursepilot-student-id，用于找回本地演示档案。旧版浏览器画像未自动迁移，旧 personalModel.ts 不再参与当前运行链路。

- app/personal.py：请求模型、DialogueProvider 协议、本地规则实现、个人学习与 API。
- app/repository.py：StudentRepository 存储接口及 JsonStudentRepository 实现。
- app/main.py：依赖装配点，将存储、课程数据、初始学生档案注入 create_router。
- app/solver.py：五维课程评分、个体 affinity 修正和课表优化。

## 数据库伙伴需要实现的接口

```python
class StudentRepository(Protocol):
    def get(self, student_id: str) -> dict | None: ...
    def save(self, student_id: str, document: dict, expected_revision: int) -> dict: ...
    def delete(self, student_id: str, expected_revision: int) -> None: ...
```

save 必须以事务进行乐观锁更新：现有 revision 必须等于 expected_revision，写入后 revision 加一，返回完整保存结果。不存在的记录仅允许 expected_revision=0 时创建。冲突抛出 app.repository.Conflict，不能覆盖已有记录。delete 同样必须检查版本。get 返回独立数据对象，不能暴露共享可变对象。

替换 main.py 中 JsonStudentRepository 的实例即可，保持 create_router 的调用不变。数据库连接池、迁移与连接环境变量由数据库实现管理。不得在仓库内提交连接密码。

建议第一阶段采用 students 表：id UUID 主键、revision 整数、document JSON/JSONB、created_at、updated_at。document 包含 profile（确认画像）、draft（待确认画像）、messages、feedback、evidence。需要查询分析时可拆分 messages、feedback、profile_versions，但一次服务调用涉及的更新仍需原子提交。

反馈字段：id、course、tags（提交时课程标签快照）、reason（interest/load/growth）、direction（-1/1）、time、source。撤回删除对应事件后重新计算参数，不在已学习参数上重复累加。

## API

完整请求与响应结构见本地 /docs（FastAPI OpenAPI）。下列路径均以 /api/students 开头。

| 方法与路径 | 用途 |
|---|---|
| POST / | 创建示例学生档案，无请求体 |
| GET /{id} | 读取完整档案，可用于管理端或导出 |
| POST /{id}/chat | revision、text，保存对话并提出画像草稿 |
| PUT /{id}/profile | revision、interests、goal、focus、challenge、exploration，人工修正 |
| POST /{id}/feedback | revision、course、reason、direction，明确反馈 |
| DELETE /{id}/feedback/{feedback_id}?revision=N | 撤回反馈 |
| POST /{id}/recommend | revision、locked、excluded，学习、求解并返回 student/profile/result |
| DELETE /{id}/draft?revision=N | 放弃待确认画像 |
| DELETE /{id}/messages?revision=N | 清除对话、提取证据及草稿，保留已确认画像和反馈 |
| DELETE /{id}?revision=N | 删除整个档案 |

不存在返回 404；版本过期返回 409，客户端重新 GET 再操作；无效请求返回 422。推荐无可行方案时返回空 schedules 和 diagnostics，保留旧确认画像及待调整草稿。成功时提交画像，但不把学习修正值写回基础偏好，因此不会重复叠加。

## 学习算法和 LLM 接口

兴趣标签证据求和 s → affinity=tanh(s/3)。单课兴趣分增加 0.35×标签 affinity 均值，再限制到 0–1。负荷与难度反馈产生 0.25×tanh((growth-load)/3) 的 challenge 修正。后端传统求解器继续检查冲突、先修与学分条件。

DialogueProvider.extract(text, profile, courses) 返回新画像、可解释变化列表、明确反馈事件。通过 create_router(provider=...) 注入真实 LLM 实现，需验证结构化输出且不得改变已修记录或正式培养要求。当前为规则模拟，无真实 LLM 或个人神经网络训练。

## 当前存储边界

默认 backend/data/students，每名学生一个 JSON。可用 COURSEPILOT_STUDENT_DIR 改目录。采用进程内锁与文件原子替换，适用于本地单进程演示，不适合多个 worker 共同写入；数据库接入后应提供跨进程事务。

目前没有身份认证：随机 UUID 仅用于本地演示查找，不是权限机制。正式部署必须由学校认证信息解析 student_id，逐接口验证所有权；管理接口应有教师或教务权限。不要直接部署为公开多用户服务。

已修记录来自 seed.json；真实教务数据适配、学期版本、身份认证和数据库迁移由后续对接完成。聊天记录目前未分页，正式数据库需补充分页、留存与删除策略。旧版 /api/solve 仍供手工工作台使用，个人助手采用后端 /recommend 链路。
