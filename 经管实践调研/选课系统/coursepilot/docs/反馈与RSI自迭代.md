# 反馈与更新及 RSI 实现说明

## 定义与范围

本项目将 RSI 实现为有界、可回退的推荐策略自迭代，不是递归改写代码或大模型自训练。课堂原型展示反馈如何影响下一轮推荐；效果来自模拟测试，未证明真实学生收益。

参考五人执行方案中 E 岗位的反馈与验证范围：区分没选上、选中后退课、修读体验；自报结果与官方结果分开；反馈自愿，不影响资格。当前落地个人反馈与推荐迭代；全校汇总、教师审核、教务供给调整仍需相应角色、官方数据与流程接入。

## 学生如何使用

登录 → 右下角选课咨询 → 反馈选课与修读情况。选择教学班，填写没选上/正在修读/退课/已完成，可填写每周课外投入和说明。重复提交同一学期同一课程更新当前状态，保留变更历史；可撤回这门课的反馈。未选上不能填修读负荷。

兴趣表达仍由对话或明确 feedback 接口收集。落选、退课、没有回复不自动转成负向兴趣。实际负荷用于本人预估误差统计及个人负荷校准，不改全体课程画像。

## 自迭代流程

1. 明确兴趣反馈自动触发一次迭代检查，也可调用 iterate。
2. 每门课程只采用最新明确兴趣反馈，至少 10 门不同课程才开始评估。样本不足记录 insufficient_data。
3. 按时间切分约 60% 训练、20% 验证、20% 测试。候选强度固定为 0.5/1.0/1.5，验证集选择候选。
4. 用测试集比较当前策略与候选的 Brier 误差，至少降低 0.01 才采用。分数范围映射只是离线偏好指标，不是经过校准的真实概率。
5. 采用时保存版本、前值、反馈指纹、评估记录和时间；否则保留旧策略。
6. 后续推荐记录使用的版本。撤回反馈或主动回退恢复基线，历史版本不直接重新上线。

强度仅影响兴趣 affinity 的有界更新；时间、先修、学分等约束仍由原求解器处理。不修改正式容量、资格、招生分配或教务规则。重复数据指纹不重新评估。同一反馈集合重复申请不应被描述为新的独立验证；未来滚动窗口需要真正的新测试批次，当前小样本评估仅作原型门槛。

## 实现位置

- backend/app/iteration.py：去重、候选评估、版本、回退与修读反馈接口。
- backend/app/personal.py：明确反馈触发、推荐参数应用、推荐版本记录。
- frontend/src/components/CourseAssistant.tsx：学生反馈入口，不展示算法参数。
- StudentRepository：继续保存档案整体，数据库接口保持不变。

## API

以下均为当前登录学生路径 /api/students/{id}：

| 接口 | 请求与行为 |
| --- | --- |
| POST /outcomes | revision、offering_id、status、可选 actual_weekly_hours/expectation/note |
| DELETE /outcomes/{course_code}?revision=N | 删除本学期该课程记录及对应历史 |
| GET /iteration?revision=N | 本人策略、历史评估、当前结果与负荷误差 |
| POST /iterate | revision；幂等检查相同反馈指纹 |
| POST /iteration/rollback | revision、version_id=baseline |

状态变更继续要求乐观锁版本。访问控制沿用账户归属验证。GET 返回技术数据供后端调试使用，学生界面不展示。

## 指标解释

- student_reported_courses：当前有自报结果的去重课程数。
- observed_load_samples：正在修读或已完成且有投入值的课程数。
- load_mae：上述样本的实际投入与课程示例预测值绝对差均值；没有样本返回 null。
- official_satisfaction_rate：目前固定 null，因为没有官方结果与同批确认需求分母。

不会用学生自报计算方案中的正式必修需求满足率；也不会把 120→95→35 的组内模拟案例包装成真实运营结果。跨学生课程反馈的匿名汇总、最小样本门槛、教师审核及发布接口尚未实施。

## 数据库交接新增字段

学生文档新增 outcomes（term:course 唯一当前记录）、outcome_history、iteration（active_gain、active_version、versions、evaluations）、recommendation_history。建议正式数据库拆为修读反馈表、策略版本表、评价表和推荐事件表，保留学生与学期关联、事务与版本检查。修读反馈为 student_report，不是 official_result。

长期运行还需记录分页、推荐日志留存、状态备份、教师/教务权限与足够样本的前瞻评估。当前单专业学期演示不宣称已经完成全校供需闭环。

## 验收与答辩口径

python backend/check_iteration.py 覆盖：可改进时采用、测试变差时拒绝、同课程重复不凑样本、同数据不重复评估、回退。
python backend/check_personal_api.py 覆盖：反馈接口、负荷样本、状态修正、撤回及原推荐链路。
python backend/check_identity.py 覆盖：登录与隔离。

答辩可说：系统把明确反馈转成个人推荐参数，并在离线指标通过门槛后采用有界候选策略，保留版本回退。不能说：已经训练出自我进化的个人 LLM，或已经证明提高正式选课成功率。


## 2026-11-24 更新：个人负荷校准

同一学期至少三门不同、已完成课程提供实际每周投入后，计算实际/原估计比率的中位数，并向 1 收缩：factor = clamp(1 + (median_ratio − 1) × n/(n+5), 0.8, 1.2)。它是可解释的启发式个人校准，不是已验证的学习能力预测。

本轮推荐对课程模型做深拷贝，仅在副本中调整 weekly_hours，影响个人负荷评分与课表总投入；原始课程说明和其他学生不变。推荐历史保存方法版本、样本数、源反馈 ID 和系数，返回值增加 calibration。课表单课说明在发生调整时注明个人校准来源。

撤回或更正反馈后，下次推荐重新计算；不足三门恢复系数 1。落选、退课、正在修读和其他学期数据不参与本版校准。当前系数用于本学期下一次推荐，不自动沿用到下一学期，跨学期衰减与迁移需要后续验证。

迭代策略评估新增 tested_courses：测试集必须含至少两门从未用于测试的课程。即使修改了反馈文本或方向，也不能将原测试课程当作新测试集；数据不足记录 waiting_new_test。既有测试集结果只保留为历史证据。

新增 python backend/check_calibration.py，验证系数界限、门槛、撤回、学期隔离及不修改共享课程。
